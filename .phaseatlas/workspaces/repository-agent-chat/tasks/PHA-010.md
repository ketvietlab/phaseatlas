# Context

PHA-009 supplies durable repository chat sessions and provider-neutral streams, but users still need a
desktop surface that feels native to PhaseAtlas rather than a raw terminal. The current renderer is
organized around repositories, workspaces, tasks, planning panels, and the Monaco workbench. Chat must
remain accessible when a repository has no workspace or when the user changes the selected task.

This task adds a repository-level chat workspace comparable to modern agent applications: multiple
conversation tabs, a readable transcript, visible agent activity, a capable composer, and reliable
reconstruction from persisted history.

# Requirements

- Add a top-level Chat action for every open repository. Opening chat must not depend on a workspace or
  task selection and must preserve the user's task/map context when closed.
- Present a session list with new, select, rename, cancel, archive/close, and interrupted-state actions.
- Render user and assistant messages as semantic conversation content, with Markdown, code blocks,
  Mermaid where safe, repository-relative file references, copy controls, and clear timestamps/status.
- Render tool and command activity as structured expandable cards with live output and completion state;
  continuously echo activity so a quiet provider is never mistaken for a frozen application.
- Provide a multiline composer with keyboard shortcuts, send/cancel states, safe repository-relative
  attachments, runner/model visibility, and a read-only mode indicator.
- Reuse the repository's provider settings. A catalog refresh or unavailable selected model must disable
  sending with an actionable explanation rather than expose free-form input.
- Restore session selection and transcript after reload. Merge persisted pages and live events by
  contiguous sequence, deduplicate events, and backfill gaps.
- Keep independent sessions capable of running concurrently. Starting or streaming one session must not
  block sending in another session or task-content initialization.
- Expose typed desktop/preload methods only for bounded chat operations; do not expose generic worker RPC,
  Electron objects, filesystem access, process control, commands, executable paths, or provider payloads.
- Meet keyboard, focus, screen-reader status, contrast, light/dark theme, responsive, and reduced-motion
  requirements consistent with the KétViệt design system.

# Implementation notes

- Extend shared desktop API contracts before adding explicit manager, IPC, and preload mappings.
- Add chat routing in `apps/desktop/src/repository-process-manager.ts` while leaving persistence, policy,
  adapters, and cancellation inside the checkout-bound worker.
- Implement the renderer as a repository-level workspace or docked panel under `apps/ui/src`, with focused
  components for session navigation, transcript, activity cards, and composer.
- Keep the remembered selected session in application-owned UI storage; worker persistence remains the
  source of truth for messages and events.
- Reuse existing Markdown rendering, terminal-stream activity language, Monaco file opening, tokens,
  badges, panels, and responsive patterns rather than adding a provider-branded design system.
- Escape provider-authored content and never turn an unvalidated path or URI into local file access.

# Constraints

- PHA-009 is the runtime authority. Do not recreate chat persistence, provider protocol parsing, sequence
  allocation, or cancellation in renderer memory.
- This task remains read-only. Edit/agent mode, worktree diffs, and acceptance/discard actions belong to
  PHA-011.
- Chat remains separate from canonical task state and execution evidence.
- Do not add provider authentication, credentials, arbitrary local attachments, general shell access,
  dependencies, or external network authority.

# Verification plan

- Open Chat from repositories with zero and many workspaces, change task/workspace selection, close and
  reopen Chat, and verify conversation state is independent.
- Run multiple sessions concurrently and confirm each transcript, activity stream, cancel control, and
  persisted cursor remains isolated.
- Reload and restart during a stream, drop selected live events, and verify replay repairs gaps without
  duplicate messages or activity cards.
- Exercise unavailable provider/model, interruption, malformed content, cancellation, and provider silence
  states; verify actionable UI and continuous activity feedback.
- Test Markdown, code, Mermaid, long output, file references, attachments, and untrusted HTML/path input.
- Complete keyboard-only, screen-reader, light/dark, narrow-width, and reduced-motion review.
- Run `pnpm check`, `pnpm test`, and `pnpm build`, then request maintainer review of the typed bridge,
  continuity logic, provider-safe rendering, and task-independent navigation.
