# Context

Read-only chat covers repository questions and planning, but users also expect a Cursor- or Codex-like
agent to edit files without leaving PhaseAtlas. A free conversation has no canonical task scope, so the
task execution policy cannot simply be bypassed or made optional. Repository mutation requires a new,
explicitly confirmed scope and an isolated worktree whose lifecycle remains auditable.

This task adds a separate chat edit attempt. It keeps conversation continuity while treating each write
turn as a bounded, reviewable operation. It also provides an optional handoff from informal dialogue to
the canonical planning publisher when work should become a tracked task.

# Requirements

- Add explicit Ask and Edit modes. Every session starts read-only; switching to Edit requires confirmation
  immediately before a write-capable provider process starts.
- The confirmation must show repository, provider, model, requested repository-relative scope, worktree
  isolation, dependency/network/database policy, and the review choices available after execution.
- Create a unique PhaseAtlas-owned edit attempt and exclusive isolated worktree. Never execute a free-chat
  write turn in the canonical checkout.
- Derive and validate changed files through Git, enforce allowed/forbidden paths and symlink containment,
  and treat model-reported changes as advisory.
- Persist normalized events, structured result, diff metadata, verification, blockers, lease lifecycle,
  cancellation, interruption, and attempt linkage using PHA-006 resilience rules.
- Present changed files and diffs for explicit review. Accept, discard, continue, and retain-for-recovery
  must have bounded, auditable semantics and must not silently alter the canonical checkout.
- Require a fresh review when the canonical base or conversation scope becomes stale. Do not apply a diff
  against an ambiguous or changed base without revalidation.
- Allow the user to create editable workspace/task proposals from selected conversation messages. The
  proposals must pass the existing canonical publisher and must not be written directly by the chat model.
- Chat output, edit results, and proposed states remain advisory and cannot mark a canonical task done or
  promote evidence.

# Implementation notes

- Define a chat edit specification distinct from `AgentRunSpec`; it has no task key but must contain an
  immutable checkout/base revision, confirmed scope, policy flags, runner/model IDs, and worktree lease.
- Generalize only the safe lease primitives needed by both task runs and chat attempts. Do not make task
  fields optional across the canonical execution scheduler.
- Reuse Git change inspection and safe path validation from `packages/core/src`.
- Add bounded worker and desktop operations for prepare/start/cancel/result/diff/accept/discard/recover.
  No operation accepts raw commands, arbitrary paths, process IDs, or worktree directories.
- Define acceptance as an explicit integration operation with base-revision checks and conflict handling.
  Retain review evidence and dispositions in application-support storage.
- Feed “Create task from conversation” through the planning proposal schema and reviewed publisher, with
  user-editable objective, scope, dependencies, criteria, and content before publication.

# Constraints

- PHA-010 and PHA-006 are required foundations.
- Do not run write-capable chat in the canonical checkout or reuse an ambiguous/abandoned worktree.
- Do not expose arbitrary shell/process/filesystem capabilities or provider permission flags.
- Do not auto-accept diffs, auto-publish tasks, auto-mark completion, or treat chat history as promoted
  evidence.
- Do not add provider credentials, dependency changes, repository database migrations, or uncontrolled
  external network access.

# Verification plan

- Confirm that read-only turns never allocate worktrees and every write turn blocks on a complete explicit
  confirmation.
- Run concurrent edit attempts and verify unique leases, worktrees, branches, streams, results, and cleanup.
- Attempt traversal, `.git` access, symlink escape, forbidden/out-of-scope changes, dependency/DB/network
  changes, stale bases, and provider permission escalation; verify fail-closed review results.
- Race cancellation, completion, acceptance, discard, and worker restart; verify one terminal disposition,
  confirmed provider exit, one lease cleanup/recovery outcome, and no post-terminal mutations.
- Review and accept a clean diff, discard another, and retain an ambiguous worktree; verify canonical checkout
  changes only through the explicit valid acceptance path.
- Generate a task proposal from selected conversation content, edit it, publish it, and verify canonical
  validation plus absence of direct chat-authored YAML or task-state transitions.
- Run `pnpm check`, `pnpm test`, and `pnpm build`, then request maintainer review of confirmation scope,
  worktree isolation, diff acceptance, recovery, and canonical-authority boundaries.
