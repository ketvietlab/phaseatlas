# Context

PhaseAtlas currently invokes model CLIs for planning, task-content generation, and validated task
execution. Every long-lived execution concept is tied to a canonical task, while ordinary repository
questions still require the user to open Codex, Claude, Cursor, or another application. Provider
settings are repository-scoped, and PHA-006 supplies durable event replay and cancellation, but there
is no task-independent conversation identity or message history.

This task introduces a separate repository chat domain. A chat session belongs to one open checkout
and one registered provider, not to a workspace or task. It reuses provider discovery and normalized
streaming boundaries without weakening task authority or treating conversation text as evidence.

# Requirements

- Define provider-neutral chat session, turn, message, attachment reference, event-page, cancellation,
  and terminal-result contracts. No chat create/send request may require or accept a workspace slug or
  task key.
- Persist session metadata, ordered user/assistant messages, normalized activity, selected runner/model,
  timestamps, and turn status in checkout-owned application-support storage.
- Support multiple independent sessions per repository and cursor-based replay after renderer, worker,
  or application restart without gaps or duplicates.
- Revalidate runner availability and the selected model against the current provider catalog before
  every turn. Provider authentication remains owned by the CLI.
- Invoke Codex CLI and Claude Code through a shared chat adapter. Provider thread/session identifiers
  remain private adapter state and never become public session authority.
- Default every conversation to read-only repository access. Unknown tool events, write attempts,
  malformed structured data, and post-terminal output fail closed.
- Normalize assistant deltas, reasoning summaries, command/tool lifecycle, file references, usage,
  completion, failure, interruption, and cancellation into shared events suitable for a chat UI.
- Keep message and diagnostic projections renderer-safe. Do not persist credentials, environments,
  executable paths, raw process handles, provider permission flags, or opaque provider payloads.
- Make cancellation idempotent and wait for the owned provider process to exit before terminalizing a
  turn. Interrupted turns remain visible and can be retried as linked attempts.
- Do not write `.phaseatlas/`, modify canonical task state, promote evidence, or infer task completion
  from a chat response.

# Implementation notes

- Extend `packages/contracts/src/index.ts` with chat-specific types rather than overloading
  `AgentRunSpec` or making task identifiers optional throughout task execution.
- Add checkout-store tables and APIs under `packages/core/src` for session metadata, messages, private
  adapter continuation metadata, ordered events, and linked turn attempts.
- Add a focused chat adapter registry under `apps/repository-worker/src`. Reuse safe runner/model
  discovery and subprocess ownership from the execution adapter boundary.
- Bind every worker operation to `PHASEATLAS_REPO_ROOT` and the current checkout identity. Public APIs
  accept only bounded session IDs, message text, safe repository-relative attachment references, and
  registered runner/model IDs.
- Persist each event before publishing it live. A reconnecting consumer first replays after its last
  contiguous sequence and then merges live events by sequence.
- Keep provider continuation IDs encrypted or private to application support if they must be retained;
  renderer-visible session IDs are PhaseAtlas-owned random identifiers.
- Document the distinction between chat sessions, planning runs, and canonical task executions in
  `docs/contracts` and an ADR.

# Constraints

- PHA-006 is a dependency for durable terminal transitions, cancellation, replay, interruption, and
  provider-process exit ordering. Reuse those primitives.
- This task provides read-only chat runtime only. Repository mutation and worktree lifecycle belong to
  PHA-011.
- Do not expose a generic CLI, shell, arbitrary command, arbitrary executable, arbitrary working
  directory, or unrestricted local attachment API.
- Do not store provider credentials or add an authentication UI.
- Do not add canonical task creation or planning publication side effects.
- Do not add dependencies, repository database migrations, or provider-branded renderer contracts.

# Verification plan

- Create two sessions in one checkout and one in a second checkout; verify histories and provider
  metadata remain isolated and survive store reopen.
- Feed equivalent Codex and Claude chat fixtures through the adapters and compare normalized ordered
  events and persisted assistant messages.
- Replay from sequence zero, an interior cursor, and the current tail while appending live events;
  verify every event is observed exactly once.
- Abort responsive and non-responsive fake provider processes; verify graceful-to-force termination,
  one terminal state, no later output, and idempotent repeated cancellation.
- Restart around an active turn; verify one interrupted transition and an explicit linked retry rather
  than silent continuation or completion.
- Submit forged runner/model IDs, task/workspace fields, unsafe attachments, write tool requests,
  credentials, paths, environment dumps, and opaque provider fields; verify fail-closed behavior and
  renderer-safe serialization.
- Run `pnpm check`, `pnpm test`, and `pnpm build`, then request maintainer review of checkout isolation,
  provider neutrality, replay continuity, and the separation from canonical task authority.
