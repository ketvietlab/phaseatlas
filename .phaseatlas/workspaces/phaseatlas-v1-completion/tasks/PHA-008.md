# Context

PhaseAtlas development currently loads the renderer from Vite and resolves the repository worker from
the monorepo build output. That is useful for local iteration but does not prove that an installed
desktop application contains every runtime component, preserves the preload sandbox, or starts without
the development server and workspace package layout.

This task establishes a fail-closed macOS packaging and verification path. Development artifacts remain
local and ad-hoc signed with updates disabled. Release artifacts require explicit signing, notarization,
and signed update metadata inputs; credentials remain external to the repository and artifact.

# Requirements

- Build the contracts, core runtime, repository worker, static renderer, Electron main process, and
  preload bridge before packaging. A missing output must stop packaging with a clear error.
- Produce a self-contained `PhaseAtlas.app` and ZIP artifact for the supported macOS architecture.
  The application must load the static renderer and bundled repository worker without Vite, pnpm, or
  workspace package resolution at runtime.
- Preserve `contextIsolation`, renderer sandboxing, disabled Node integration, typed preload exposure,
  navigation restrictions, and repository-worker checkout binding in the packaged application.
- Embed a versioned release policy. Development artifacts must disable update activity and contain no
  signed-update configuration. Release artifacts must require manual update initiation and verified
  signed metadata.
- Fail release packaging before artifact publication when the signing identity, notarization profile,
  HTTPS update feed, public key, manifest, or signature is absent or invalid. Never embed private keys,
  credentials, provider authentication, or environment files.
- Generate a bundle manifest with SHA-256 digests for PhaseAtlas-owned runtime files and verify its path
  containment and contents before executing the smoke test.
- Verify code signing and launch the packaged executable with isolated application-support state. The
  smoke test must confirm that the static renderer loads and a bundled worker can inspect a real
  repository, then exit deterministically.
- Document supported-platform packaging, development verification, release signing/notarization,
  installation, manually initiated update validation, rollback, and evidence capture procedures.

# Implementation notes

- Keep packaging orchestration in repository scripts and derive paths from the repository root. Do not
  move packaging or policy logic into the renderer.
- Bundle JavaScript dependencies into the Electron and repository-worker outputs while keeping Electron,
  Node built-ins, `node:sqlite`, and the native `node-pty` module external where required.
- Copy only the native runtime package required by the worker. Verify the final application layout rather
  than trusting source-tree presence.
- Read the application version from the root package manifest and use it consistently in the bundle,
  archive name, and macOS metadata.
- Treat update metadata verification as an offline packaging gate. Development and test execution must
  not contact an update server, and PhaseAtlas must not enable background update checks.

# Constraints

- macOS is the only supported packaging host for this milestone. Other platforms must fail with an
  explicit unsupported-host message.
- Do not add a packaging dependency, auto-updater, credential store, remote build service, or generic
  process/filesystem capability to the renderer.
- Do not weaken sandbox settings, accept HTTP update feeds, silently fall back to unsigned release
  artifacts, or make signing/notarization optional for the release channel.
- Do not publish, upload, install, or replace an existing application automatically.

# Verification plan

- Run `pnpm check`, `pnpm test`, and `pnpm build` with Node 24 or newer.
- Package a development artifact and verify bundle layout, manifest digests, code signing, static
  renderer load, bundled worker startup, and deterministic smoke-test exit.
- Run release packaging without each required input and confirm it fails before deleting or producing a
  release artifact. Validate that HTTP update feeds and invalid signatures are rejected.
- Inspect the packaged resources for credential-like files and workspace JavaScript imports.
- Install a verified artifact manually in a disposable location, launch it with fresh application data,
  and record the application version, signing verification, repository inspection result, and artifact
  SHA-256 as release evidence.
- For rollback, retain the prior verified ZIP and bundle digest, stop PhaseAtlas, replace the application
  manually, and confirm the prior version against its recorded evidence before reopening repositories.
