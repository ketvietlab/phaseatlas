# Context

`packages/contracts/src/index.ts` already declares `AgentRunSpec` and a normalized `AgentEvent` union, and `packages/contracts/schemas/agent-run-result.schema.json` describes structured final output. These contracts are not yet connected to an execution runner: the repository worker only supports read-only planning and task-content generation, the result schema is not exported or paired with a TypeScript result type, and `RunnerDescriptor` reports planning-oriented capabilities only.

`apps/repository-worker/src/runner-registry.ts` contains Codex CLI and Claude Code planning adapters, but their process arguments, stream formats, structured-output mechanisms, and error handling remain provider-specific. Codex progress is converted into display text while raw stderr can still be forwarded, and there is no shared execution interface that translates both providers into `AgentEvent` and a validated run result.

PHA-004 supplies validated immutable run specifications, trusted sandbox selection, and scheduler-owned checkout or worktree leases. This task exists to add the provider boundary on top of that foundation so subsequent execution resilience and workbench tasks can consume one stable contract without learning either provider’s protocol.

# Requirements

- Extend the shared runner contracts with provider-neutral discovery for execution support, supported actions, sandbox modes, streaming, structured output, and live cancellation. Capability checks must reject unsupported action or sandbox combinations before a provider process starts.
- Define and export an `AgentRunResult` TypeScript contract aligned with `packages/contracts/schemas/agent-run-result.schema.json`, and export the schema through `@phaseatlas/contracts` for adapter and runtime validation.
- Introduce a provider-neutral execution adapter interface that accepts the immutable `AgentRunSpec`, scheduler-selected execution directory and sandbox context from PHA-004, an abort signal, and a normalized event sink. It must not accept renderer-supplied executable paths, working directories, raw commands, credentials, or process handles.
- Implement execution support for both existing registered providers: Codex CLI and Claude Code. Each adapter must translate the same validated specification into its provider-specific invocation while preserving the specification’s action, objective, context, scope, acceptance criteria, verification steps, and sandbox policy.
- Normalize provider output into the shared `AgentEvent` variants. Sequence numbers must be assigned or validated by trusted shared code, remain strictly increasing, and preserve the observable order of status, text, command, file, turn, and failure events.
- Validate each provider’s structured final output before returning it. Successful completion requires a schema-valid normalized result; missing output, malformed JSON, schema violations, or conflicting terminal data must fail closed and emit a normalized failure event.
- Treat unknown provider events safely and reject provider requests for actions, tools, permission modes, or sandbox behavior not authorized by the descriptor and run specification. A provider-specific success indication must not bypass shared result validation.
- Keep provider authentication in the provider CLI or provider-owned environment. Public descriptors, worker responses, normalized events, errors, and results must exclude credentials, environment dumps, executable paths, raw child-process objects or identifiers, and provider-only permission flags or payloads.
- Support cancellation at the adapter boundary by honoring the supplied abort signal and terminating the owned live process without exposing that process to callers. Emit one normalized terminal failure or cancellation status according to the shared execution contract; durable, resumable cancellation behavior remains a later task.
- Preserve the authority boundary around results: `proposedTaskState` is advisory, and neither adapter nor registry may write canonical task files, promote evidence, or mark a task complete.
- Discover selectable models from the installed and authenticated provider CLI. The renderer must receive only a bounded model descriptor projection and must not offer free-form model input, hardcoded model catalogs, or arbitrary executable-path settings.
- Provide repository-scoped provider settings for the supported CLI and selected discovered model. The setting must survive renderer reload, remain outside `.phaseatlas/`, and be reused by planning and task-content initialization for that checkout.
- Validate every selected model again in the repository worker immediately before provider handoff. A stale, forged, or manually injected model ID that is absent from the current runner descriptor must fail closed.

# Implementation notes

- Update `packages/contracts/src/index.ts` first. The current `RunnerCapability` union contains only `planning`, `streaming`, `structured_output`, and `repository_read`; evolve it and `RunnerDescriptor` without introducing provider flags into renderer-visible types. Align `AgentEvent`, execution inputs, normalized failures, and `AgentRunResult` with the scheduler and persistence contracts delivered by PHA-004.
- Import and export `packages/contracts/schemas/agent-run-result.schema.json` in the same manner as the task proposal and task content schemas. Keep the JSON Schema strict and synchronized with the TypeScript result shape, including the distinction between `outcome` and advisory `proposedTaskState`.
- Refactor `apps/repository-worker/src/runner-registry.ts`, where `PlanningRunnerAdapter`, `CodexPlanningAdapter`, `ClaudePlanningAdapter`, `runChildProcess`, provider discovery, and stream parsing currently coexist. Planning may remain supported, but execution should use a distinct provider-neutral interface or an explicit execution facet rather than widening planning methods with provider-specific conditionals.
- Reuse the current stable runner IDs, `codex-cli` and `claude-code`, and the provider selection established by `docs/decisions/0004-provider-neutral-planning.md`. Keep Codex JSONL parsing and Claude stream-JSON parsing behind their adapters.
- Replace execution-facing forwarding of raw stderr or arbitrary provider lines with sanitized normalized diagnostics. Provider event fields such as Codex thread IDs, Claude permission modes, executable locations, and opaque tool payloads must not enter public worker events.
- Integrate execution dispatch in `apps/repository-worker/src/index.ts` with the validated scheduler and lease handoff from PHA-004. The repository worker remains bound to `PHASEATLAS_REPO_ROOT`; adapters receive only the trusted canonical checkout or leased worktree directory selected for that run.
- Add fixture-driven tests in `apps/repository-worker/src/runner-registry.test.ts` or focused test files under `apps/repository-worker/src`. Inject process launching and fixture streams so tests do not require installed or authenticated provider CLIs.
- Extend `RunnerDescriptor` with a renderer-safe model catalog containing only stable model ID, display name, provider default status, and supported reasoning-effort labels. Codex discovery projects `codex debug models` output; Claude discovery projects aliases advertised by the installed Claude Code CLI. Discovery failure leaves the model picker disabled instead of falling back to user input.
- Add one repository settings dialog in `apps/ui/src/routes/+page.svelte`. Store only `{runnerId, modelId}` under the checkout ID in application-owned local storage, share that selection with planning and content initialization, and replace the planning studio model text field with the same catalog-backed selector.
- Update `docs/contracts/agent-run-contract.md` with adapter inputs, capability negotiation, sequence ownership, structured-result validation, normalized failure behavior, cancellation boundaries, and the renderer-safe projection.
- Expand `docs/decisions/0004-provider-neutral-planning.md` to record that the same provider-neutral boundary now covers execution, while documenting the provider-specific details that remain private to adapters.

# Constraints

- PHA-004 must provide validated run-spec creation, sandbox derivation, trusted working-directory selection, and exclusive worktree leases. Do not recreate or weaken those controls inside provider adapters.
- Never execute a write-capable run in the canonical checkout. An adapter must not override the scheduler-selected directory or silently downgrade an unsupported sandbox.
- Keep execution and provider process management in the repository worker. Do not move them into Electron main, preload, or the Svelte renderer, and do not expose arbitrary command execution through shared IPC contracts.
- Do not add the execution-history UI or workbench; that belongs to PHA-007. The repository provider settings surface is explicitly in scope, but execution history, action controls, and result review are not.
- Do not implement persisted resume, stale-result promotion safeguards, or full idempotent cancellation recovery; those belong to PHA-006. This task is limited to capability reporting and correct cancellation of the adapter’s live process.
- Do not add dependency changes, database migrations, external network authority, new credential storage, or provider authentication flows.
- Do not accept renderer-supplied executable paths or provider commands. CLI selection is limited to stable registered runner IDs; authentication and executable resolution stay behind the worker adapter boundary.
- Do not persist raw provider payloads, complete environment data, credentials, or process handles. Operational events and results must use shared normalized contracts.
- Treat all provider output as untrusted. No result may directly modify `.phaseatlas/`, promote evidence, or transition a canonical task.

# Verification plan

- Add contract tests that compare representative `AgentRunResult` values against both the exported TypeScript expectations and `AGENT_RUN_RESULT_SCHEMA`, including every outcome, verification status, evidence type, and optional proposed state.
- Test runner discovery with injected available and unavailable CLIs. Assert that Codex CLI and Claude Code expose provider-neutral execution, sandbox, streaming, structured-output, and cancellation capabilities without provider permission flags or executable paths.
- Feed equivalent recorded Codex JSONL and Claude stream-JSON fixtures through their execution translators. Assert that both produce the same ordered normalized `AgentEvent` sequence and equivalent schema-valid `AgentRunResult` values.
- Cover status, text delta, command start/output/completion, file change, turn completion, and terminal failure translation. Assert that normalized sequence numbers are strictly increasing and that provider-supplied duplicate or regressing sequences cannot enter the accepted stream.
- Exercise malformed JSON, missing structured output, schema-invalid results, unknown terminal payloads, unsupported actions, and unsupported sandbox requests. Assert that each case fails closed, returns no successful result, and emits one normalized terminal failure.
- Include adversarial provider fixtures containing credential-like values, full executable and repository paths, raw process identifiers, environment dumps, and provider-only permission flags. Inspect serialized descriptors, events, errors, and results and assert that none of those private values cross the public worker boundary.
- Use an injected fake child process to abort active Codex and Claude executions. Assert that the adapter terminates only its owned process, stops accepting subsequent provider output, and exposes no raw handle to its caller.
- Exercise the PHA-004 integration with fake scheduler contexts for read-only and workspace-write runs. Assert that adapters use exactly the trusted directory and sandbox supplied by the scheduler and reject attempted provider overrides.
- Feed representative Codex and Claude catalog output into pure parsers. Assert hidden or malformed entries and provider-private fields are omitted, repository preferences restore only an ID present in the current catalog, and a forged model ID is rejected by the worker.
- Reload the renderer and switch between two repositories with different saved selections. Verify each checkout restores its own supported CLI and model, both model selectors show identical provider-derived options, and no text field can submit an arbitrary model or executable.
- Run `pnpm check`, `pnpm test`, and `pnpm build` with Node.js 24.14.0 or newer and the root-pinned pnpm 11.9.0.
- Request PhaseAtlas maintainer review of capability neutrality, both provider translations, sequence enforcement, fail-closed result handling, cancellation ownership, renderer-safe serialization, and the prohibition on direct canonical task completion.
